## 当前技术栈

| 层次 | 技术与版本 | 作用 |
| --- | --- | --- |
| 后端 | Java 17、Spring Boot 3.2.0、Spring MVC | REST 接口、上传、静态网页 |
| 构建 | Maven，本机 3.9.16 | 依赖和可执行 JAR 打包 |
| AI Agent | Spring AI 1.1.0、Spring AI Alibaba 1.1.0.0-RC2 | ReactAgent 工具调用，SupervisorAgent 编排 Planner/Executor |
| 当前聊天 | Spring AI OpenAI 客户端，中转模型 deepseek-flash | 普通聊天、流式聊天、Agent、RAG 生成 |
| 当前向量化 | Ollama 0.34.0、bge-m3，1024 维 | 多语言知识库向量化；无需发送文档至向量化云服务 |
| 向量库 | Milvus 服务端 2.5.10、Java SDK 2.6.10 | biz 集合、IVF_FLAT 索引、L2 检索 |
| 配套存储 | etcd 3.5.18、MinIO RELEASE.2023-03-20T20-16-18Z | 元数据与对象存储 |
| 管理界面 | Attu 2.5 | Milvus 数据管理 |
| 网页 | 原生 HTML/CSS/JavaScript、SSE | Spring Boot 直接托管，无需 npm 构建 |
| 流式连接 | Reactor Netty HTTP 客户端 | 连接与响应超时，IPv4 网络配置 |
| Markdown/高亮 | marked 11.1.1、highlight.js 11.9.0 | 页面从 jsDelivr CDN 加载 |
| 运维集成 | Prometheus HTTP API、腾讯云 CLS MCP/SSE | 当前使用内置模拟告警和日志 |
| 原有模型支持 | DashScope SDK 2.17.0 | 默认源码配置仍保留 DashScope 分支 |

主流程：上传 txt/md → 文档切片 → 本地 bge-m3 → Milvus；Agent 查询知识库后，将检索到的上下文发给聊天中转生成答案。智能运维由 SupervisorAgent 协调 Planner 与 Executor。

项目无需另装 Node.js、MySQL、Redis 或本地聊天大模型。会话历史保存在 Java 内存中，应用重启后不保留。

## 启动与停止

在 PowerShell 中执行：

```powershell
Set-Location 'D:\oncall\SuperBizAgent-release-2026-01-02\SuperBizAgent-release-2026-01-02'

# 启动：容器、独立向量服务、后台 Java 服务
powershell -ExecutionPolicy Bypass -File .\deployment\start-local.ps1

# 停止本项目 Java、数据库容器和独立向量服务，保留模型和数据
powershell -ExecutionPolicy Bypass -File .\deployment\stop-local.ps1

# 重新构建后启动（应先停止现有 Java 服务）
powershell -ExecutionPolicy Bypass -File .\deployment\start-local.ps1 -Build

# 只启动数据库
powershell -ExecutionPolicy Bypass -File .\deployment\start-local.ps1 -DatabaseOnly

# 查看数据库状态
docker compose -p superbizagent -f .\deployment\compose.local.yml ps

# 单独构建
mvn -s .\deployment\maven-settings.xml -B -ntp package
```

启动脚本优先读取当前会话或 Windows 用户环境变量 `RELAY_API_KEY`，没有时读取本机加密文件。`start-embedding.ps1` 使用独立的 11435 端口和模型目录；模型已存在时不会重新下载。启动脚本会检查业务数据库健康状态，成功后输出 Ready。

聊天模型、地址和向量化设置在 `deployment/application-local.yml` 中。配置中只有环境变量占位符，没有密钥。当前 base-url 为 `https://api.apigoto.com`，客户端自动追加 `/v1/chat/completions`。当前推理强度配置为 low；报告可能因中转负载耗时数分钟。

若需要更换 Key，可在本机隐藏输入后重新保存：

```powershell
$secureKey = Read-Host '请输入新的中转 Key' -AsSecureString
$secureKey | Export-Clixml 'D:\tools\superbizagent-config\apigoto-key.xml'
```

修改 Key 后重新启动 Java 服务。迁移到另一台电脑或 Windows 用户时需重新保存密钥。

## 实现说明与限制

- 原项目硬编码使用 DashScopeChatModel；现改为通用 ChatModel，可由配置选择中转或 DashScope。
- 当前中转模型列表没有 Embedding 模型，测试 text-embedding-3-small 返回不可用，因此使用本地 bge-m3。
- HTTP 客户端配置了同步调用超时；流式连接使用 Reactor Netty、连接/响应超时、最多两次连接阶段重试和 IPv4。发送响应内容前才重试，避免重复已经展示的文本。
- 本机实测两个中转地址的 TLS 1.3 握手超时，TLS 1.2 均正常。项目中转客户端已配置 TLS 1.2，保持证书验证、正常 DNS 解析和连接阶段重试。模型推理与多 Agent 报告本身仍可能耗时较长。
- Milvus 1024 维结构与 bge-m3 一致；以后更换向量模型时需要重新索引知识库，不能混用不同模型的向量。
- 真实监控需要配置实际 Prometheus、有效腾讯云日志 MCP，并关闭 mock；此次没有配置真实监控。
- 中转生成答案时会接收用户问题和工具检索到的文档内容。
- 前端 API 地址写死为 localhost:9900，当前用于本机访问；迁移域名或远程访问时需调整。
- README 的 Milvus 2.6.10 是 SDK 版本，服务端实际为 2.5.10；Replanner 职责由 Planner 承担。

## 新版平台交互（已接入）

根路径 `/` 默认进入 `/designs/workbench-v2.html`，故障深挖为 `/designs/incident-v2.html`，知识问答为 `/designs/knowledge-v2.html`；历史页面保留在 `/designs/` 的归档区。

当前中转 https://api.apigoto.com，模型 deepseek-flash；密钥保存于 D:/tools/superbizagent-config/apigoto-key.xml，不提交源码。

新版接口提供告警、日志、上传文档目录、文档内容和流式问答。知识问答页面支持“知识库优先”和“通用问答”两种模式：知识库优先会先检索 Milvus，资料匹配时依据召回片段回答，资料不足时自动使用通用知识补充并明确标注；通用问答完全不检索知识库，直接调用模型。请求字段 mode=knowledge/general，缺省为知识库优先。上传成功表示向量索引完成。检索来源是实际召回片段，不表示每个片段均被答案引用；L2 距离不等于可信度。

告警和日志当前为后端模拟数据，没有真实时序指标或发布事件。诊断由带工具的 ReactAgent 生成，报告保存在浏览器会话。会话未实现数据库持久化。
